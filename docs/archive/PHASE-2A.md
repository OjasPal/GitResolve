PART 2 - GRAPH (COMMIT 3, after AL)
Replace run_repair()'s one-shot loop with a real StateGraph, the model-tool-model cycle inside the graph, per ROADMAP decisions. Lanes (from AL) are graph structure:
 intake/triage (AL TriageReport) -> repo_profile -> env_prepare (+ baseline from cache/prewarm) -> lane router
  FAST lane: deterministic localize (traceback/grep/AST) -> single patch call with minimal context (NO explore loop) -> static_check (AL oracle + post-patch planner) -> verify at the planner's level -> minimal-context review -> finalize
  FULL lane: explore (tool loop) -> reproduce -> patch (tool loop) -> static_check -> verify (full suite) -> review -> finalize
  ESCALATION: any fast-lane node can route to explore carrying its evidence; monotonic, never back to fast. Failures route back to explore/patch with classified evidence, never blind full regeneration.
Typed RepairState with reducers (messages, attempts); logs/files go to bounded artifacts, not checkpoints. Tool registry with path/symlink/protected-file/size validation and no host shell: list_tree, grep, read_file(path,start,end) numbered, find_symbol/find_references (ast), run_tests, run_check, run_snippet (check sandbox/models.py command validation; extend narrowly), edit_file (exact/whitespace-tolerant/line-range), create_file, git_diff, ask_user, report_blocker, finish. Invalid action/args -> structured error back to the model, never a crash. Every execution tool calls ctx.execute(commit_sha, command, patch=overlay_patch) in a fresh hardened container. Enforce budgets in code, call ctx.checkpoint() every step, emit bounded EventType.TOOL_CALL events (tool, safe path, duration, result summary, attempt): actions and evidence only, no hidden reasoning. Keep: regression-before/after evidence, full suite (full lane; planner-selected level otherwise), independent review, policy gate, validate_patch, exact-diff approval.
